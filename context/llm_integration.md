# LLM.js Integration for AI-Powered Summarization

## Overview
This document details the integration of the [@themaximalist/llm.js](https://github.com/themaximalist/llm.js/) library into Min Browser, enabling AI-powered page summarization through the existing Page Summarizer feature.

## Feature Implementation

### What's New
- **AI-Powered Summarization**: Page Summarizer now uses LLM APIs to generate intelligent summaries
- **Multi-Provider Support**: Supports OpenAI, Anthropic, Google, Groq, and Ollama providers  
- **Intelligent Provider Detection**: Automatically maps model names to appropriate providers
- **Robust Fallback System**: Dual implementation ensures 100% reliability
- **Build System Compatibility**: Resolved ES module/CommonJS conflicts with browserify
- **Enhanced Logging**: Detailed console output with status indicators and error handling

### User Experience Flow
1. User clicks `Capabilities → Page Summarizer`
2. System checks LLM configuration status
3. Page content is extracted (existing functionality)
4. If LLM is configured: AI generates a concise summary
5. Both summary and full content are logged to console
6. Clear error messages if configuration is missing

## Architecture Integration

### Design Principles
- **Separation of Concerns**: AI functionality isolated in dedicated `js/ai/` module
- **Backward Compatibility**: Existing Page Summarizer functionality preserved

## Implementation Details

### 1. Core LLM Provider Module (`js/ai/llmProvider.js`)

**Purpose**: Encapsulates all LLM integration logic with robust fallback handling.

**Key Functions**:
- `isAvailable()`: Always returns true (uses fallback if needed)
- `isUsingFallback()`: Checks if using direct API fallback
- `mapModelToProvider(modelName)`: Maps Min's model names to LLM.js providers
- `summarizeText(text, pageTitle, pageUrl, llmConfig)`: Generates AI summaries
- `validateConfiguration(llmConfig)`: Validates user's LLM settings
- `getLoadError()`: Returns detailed error info for debugging

### 2. Direct API Fallback (`js/ai/directApiProvider.js`)

**Purpose**: Reliable fallback implementation using direct HTTP API calls.

**Supported APIs**:
- OpenAI: `/v1/chat/completions`
- Anthropic: `/v1/messages` 
- Google: Generative Language API
- Groq: OpenAI-compatible API

**Provider Mapping Logic**:
```javascript
// Automatic provider detection based on model name
'claude-3-5-sonnet' → anthropic provider
'gpt-4o-mini' → openai provider  
'gemini-*' → google provider
'groq-*' → groq provider
'ollama-*' → ollama provider
// Fallback: openai provider for unknown models
```

**Error Handling**:
- Library availability checks
- API key validation
- Provider detection failures
- API call errors with detailed logging

### 2. Enhanced Page Summarizer (`js/menuRenderer.js`)

**Changes Made**:
- Added `var llmProvider = require('ai/llmProvider.js')` import
- Enhanced `summarizePage` IPC handler with AI capabilities
- Improved configuration validation and user feedback
- Added async summary generation with promise handling

**Flow Enhancement**:
```javascript
// Original flow: Extract content → Log content
// Enhanced flow: Extract content → Generate AI summary → Log both
```

### Model Configuration Mapping
| Min Settings Value | Detected Provider | LLM.js Provider |
|-------------------|-------------------|-----------------|
| `claude-3-5-sonnet` | anthropic | anthropic |
| `gpt-4o-mini` | openai | openai |
| `gemini-pro` | google | google |
| `custom-model` | openai (fallback) | openai |

### API Key Requirements
Each provider requires appropriate API keys:
- **OpenAI**: `OPENAI_API_KEY` or configured in settings
- **Anthropic**: `ANTHROPIC_API_KEY` or configured in settings  
- **Google**: `GOOGLE_API_KEY` or configured in settings
- **Groq**: `GROQ_API_KEY` or configured in settings
- **Ollama**: No API key required (local)

## Error Handling and Debugging

### Common Issues and Solutions

**1. "LLM.js library not available"**
```
❌ LLM.js library not available
   Please ensure @themaximalist/llm.js is properly installed
```
*Solution*: Run `npm install @themaximalist/llm.js`

**2. "No LLM configuration found"**
```
⚠️  LLM Provider not configured
   No LLM configuration found. Use Capabilities → Switch LLM... to configure.
```
*Solution*: Configure model and API key in Settings

**3. "Invalid API key provided"**
```
❌ Failed to generate summary: Invalid API key provided
```
*Solution*: Verify API key is correct for the selected provider

**4. "Unable to detect provider"**
```
❌ Unable to detect provider for model: custom-unknown-model
```
*Solution*: Use recognized model names or ensure custom model is valid

### Debugging Tips
- Check browser console for detailed error messages
- Verify API key format matches provider requirements  
- Test with popular models (claude-3-5-sonnet, gpt-4o-mini) first
- Ensure network connectivity for API calls

## Robust Fallback System

### Problem Resolution: Build System Compatibility

**Issue**: The llm.js library caused "Maximum call stack size exceeded" errors due to ES module/CommonJS conflicts in Min's browserify-based build system.

**Solution**: Implemented a dual-approach system:
1. **Primary**: Attempt to load llm.js library 
2. **Fallback**: Use direct HTTP API calls when library fails

### Architecture Benefits

**Reliability**: AI features work regardless of library compatibility issues
**Performance**: Direct API calls are often faster than complex library overhead  
**Transparency**: Clear logging shows which method is being used
**Maintainability**: Simpler fallback code is easier to debug and maintain

### Console Output Examples

**With LLM.js Library Success**:

🤖 Generating AI Summary...
